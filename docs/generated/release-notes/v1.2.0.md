## maverick-mcp-server v1.2.0

Published by the tag-triggered workflow: the GHCR image
`ghcr.io/wshobson/maverick-mcp:1.2.0`. PyPI and the official MCP Registry
are still pending: the PyPI name `maverick-mcp-server` is held by a dormant,
unrelated project, and a PEP 541 name-transfer request is open with PyPI.
Do not install `maverick-mcp-server` from PyPI until the README says the
name is ours; install from the release tag or run the image instead.

The server has 53 tools: 38 core, 12 backtesting, and 3 research.

### Upgrade notes

- **Docker data moves to `/data`.** The image now defaults to
  `sqlite:////data/maverick.db` and `/data/maverick_cache.db`. The 1.1.0 image
  kept them under `/app`, so back up those files before replacing an old
  container, then mount a named volume at `/data`. See
  `docs/runbooks/database-setup.md#docker-data-storage` (#310).
- **Response changes.** These are additions or corrections, but a client that
  read the old values will see different ones:
  - Journal add, close, and review results keep the trade's `open`/`closed`
    state in `trade_status`; `status` stays the call's `success`/`error`
    (#318, @vishalhabib99).
  - Backtest metrics annualize over 252 trading sessions instead of 365 days,
    and a profit factor with no losing trades is `null` with a status field
    instead of `0` (#310).
  - Backtesting tool responses cut `equity_curve` and `drawdown_series` to 60
    evenly spaced points, and trade lists are bounded with omission counts
    (#299, #310).
  - `backtest_portfolio` and `compare_strategies` list symbols that failed in
    a new `failed` field (#299).
  - Research returns an `insufficient_evidence` error when no sources survive
    validation, instead of synthesizing from nothing (#310).
  - Support and resistance are the observed extremes over the stated window,
    and risk confidence is reported as unavailable rather than invented
    (#310).
- **Dependency floors.** numpy>=2.5.3, pandas>=3.0.5, and vectorbt>=1.1.0.
  `pandas-ta` is gone; the ML features use the in-house indicator core (#271).
  Unused direct dependencies were dropped, including core `openai`,
  `anthropic`, `uvicorn`, `cryptography`, and `pytz` (#286).

### Fixes

- **Portfolio persistence.** Database writes are serialized so concurrent
  calls cannot lose an acknowledged purchase, and positions round to the
  precision their columns store, so selling exactly what you bought closes the
  position (#287, #310).
- **Backtests no longer see the future.** Inputs are causal, trade durations
  come from timestamps, and ATR sizing is consistent (#310).
- **Adjusted price history.** Stored history refreshes once it is 24 hours old
  and never mixes bars adjusted on different bases (#310).
- **Circuit breaker recovery.** A cancelled or stale call can no longer leave
  a provider's breaker stuck half-open until restart (#273, fixes #272,
  @adity982).
- **Quotes and symbols.** A quote with no usable price is an error instead of
  `success` with price 0, and a dotted class share such as `BRK.B` retries as
  `BRK-B` (#299).
- **Market movers.** Top gainers and losers are ranked by real percent change
  with correct tickers again, after finviz changed its page (#300).
- **Screening.** A fresh install with no symbols explains how to add them
  instead of screening nothing, and rubric scoring runs off the event loop
  (#287, #299).
- **Journal.** `portfolio_journal_add_trade` takes an optional `entry_date`,
  and prices, shares, and exit dates are validated (#299, #310).
- **Input validation.** Unknown watchlist IDs and invalid risk values return
  errors, and malformed LLM scores no longer crash research synthesis (#311).
- **Regime detection.** A detector that fell back to `threshold` retries the
  requested method on a later, larger fit (#285).
- **Watchlists.** A read-only watchlist listing tool is new (#310).

### Build and testing

- The Docker image is multi-stage: 1.2 GB instead of 2.27 GB, with no uv or
  compiler in the runtime stage (#286).
- CI installs the core wheel with no extras and builds from an extracted
  source archive (#310). A process end-to-end harness runs all 53 tools over
  real STDIO and HTTP servers (#311).

### Install

```bash
# Run the release tag straight from GitHub (add extras with
# "maverick-mcp-server[backtesting,research] @ git+...")
uvx --from "git+https://github.com/wshobson/maverick-mcp@v1.2.0" maverick-mcp --transport stdio

# Or the image: Streamable HTTP on port 8000 inside the container
docker run --rm -p 127.0.0.1:8003:8000 \
  --mount source=maverick-data,target=/data \
  ghcr.io/wshobson/maverick-mcp:1.2.0
```
